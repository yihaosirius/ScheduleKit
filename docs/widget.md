# Scriptable 小组件

在主屏常驻显示任务，不用打开 App。

脚本：[`clients/scriptable/schedulekit-widget.js`](../clients/scriptable/schedulekit-widget.js)

---

## 安装

1. App Store 装 **Scriptable**（免费）
2. 网页控制台 → 设置 → API Key → 新建，名字填 `widget`，**勾上「只读」**
   - 小组件只需要 `GET`，只读 Key 就算泄漏了也改不了你的任务
3. 复制 `clients/scriptable/schedulekit-widget.js` 的内容
   → Scriptable 里点 `+` 新建脚本 → 粘贴 → 命名 `ScheduleKit`
4. 长按主屏空白处 → 左上角 `+` → 找到 Scriptable → 选一个尺寸
5. 添加后**长按小组件 → 编辑小组件** → 在 `Parameter` 里填：

   ```
   https://canisa1ph.duckdns.org:8443|sk_你创建的只读Key
   ```

   （中间是一个竖线 `|`）

6. 想换尺寸就再添加一个，参数填一样的即可
7. **锁屏组件**：长按锁屏 → 自定义 → 添加小组件 → Scriptable，
   选择「矩形 / 圆形 / 内联」中的一个，参数同样填上面那串

## 支持哪六种尺寸

| 位置 | 尺寸族 | 内容 |
|---|---|---|
| 主屏 | **小** | 最紧要的 3 条**带截止时间**的任务（按截止时间升序）。若一条都没有，退回显示优先级最高的 3 条 |
| 主屏 | **中** | 左右分栏：左「待截止」3 条、右「待排序」3 条 |
| 主屏 | **大** | 「待截止」6 条 + 「待排序」4 条 |
| 锁屏 | **矩形** | 两行：`• 交第三章习题  2天` / `10月4日 23:59 …… 另 8 条` |
| 锁屏 | **圆形** | 两行：倒计时 + 极短标题（四角会被裁，只放一条） |
| 锁屏 | **内联** | 一行纯文本：`交第三章习题 · 2天`（在时间旁边，只能一行） |

### 锁屏与主屏是**两套实现**，不是同一套缩放

这一点值得单独说明，因为它决定了改代码时该动哪里：

| | 主屏 | 锁屏 |
|---|---|---|
| 空间 | 有富余 | 矩形约两行，圆形四角被裁 |
| 颜色 | 彩色，可表达紧急度 | **系统渲染成单色**，颜色基本无效 |
| 背景 | `Color.dynamic` 跟随深浅色 | 不要设背景（没有深浅色概念） |
| 字色 | 系统默认 | `Color.white()` |
| 状态表达 | 靠颜色（逾期红、24h 内橙） | 靠**形状与文字**（`•` / `Ⅰ` / 倒计时） |
| 内联 | 不存在 | 只能是一行 `addText`，不能加 stack |

所以锁屏族走 `renderAccessory()`，完全不与主屏共用布局代码。
只有取值与文案函数（`shortDue` / `whenLabel` / `dueState`）是共用的。

### 主屏的倒计时

标题右侧的倒计时（`2天` / `3时`）由脚本按本地时间算。
**逾期会变红**，24 小时内到期变橙色。已完成的任务不显示倒计时，
改显示"完成于 …"——已经做完的事没有再显示时间压力的道理。

## 凭据放在哪里

**推荐放在小组件的 `Parameter` 里**（上面的做法）。

理由：脚本内容可能被分享、备份、贴到别处，写死就等于把 Key 一起带走了；
而 Parameter 存在系统的小组件配置里，不随脚本走。

如果你更谨慎，脚本也支持从 **Keychain** 读：

```js
// 在 Scriptable 里新建一个脚本，只跑一次：
Keychain.set("schedulekit_key", "sk_你的只读Key");
```

之后 `Parameter` 只填 `https://canisa1ph.duckdns.org:8443` 即可，Key 会自动从
Keychain 取。注意 Keychain 在 iCloud 备份里是加密的，但仍然建议用只读 Key。

**不要**把 Key 直接写进脚本源码（除非你确定这份脚本永远不会离开这台设备）。

## 刷新时机

脚本里设了 `refreshAfterDate = now + 15min`。

iOS **不保证**按这个时间刷新——它只是"不早于"。实际刷新频率受系统调度、
充电状态、使用习惯影响，可能几十分钟到几小时一次。

如果想立刻刷新：打开 Scriptable App 点一下脚本运行，
或者移除小组件再添加（比较麻烦）。

**这也是为什么后续值得做推送**：小组件只能"被拉取"，不能"被通知"。
见 [`push-notes.md`](push-notes.md)。

## 离线与失败时的行为

| 情况 | 主屏表现 | 锁屏表现 |
|---|---|---|
| 网络失败但有缓存 | 显示**上一次成功的数据**，标题右侧标 `离线`（橙色） | 显示缓存数据（锁屏没有位置放"离线"标记，矩形空态时才写"离线，无缓存"） |
| 网络失败且无缓存 | 红色错误文案 + "检查网络，以及 Key 是否被吊销" | `加载失败` / `离线`（极短） |
| 没配 Parameter | 显示**怎么配**的提示（不是空白组件） | `未配置` |
| Key 被吊销 | 加载失败（401），显示错误文案 | 同上 |

缓存存在 Keychain 里（`schedulekit_widget_cache`），只保存最近一次成功的响应。

**故意不让失败变成空白**：一个空白小组件无法区分"没任务"和"加载失败"，
而这两件事需要完全不同的反应。锁屏上空间不够写完整提示，但至少会给一个词，
而不是一片空白。

**主屏会自动刷新**（`refreshAfterDate` = 15 分钟后）。锁屏组件的刷新时机由
系统决定（通常跟随锁屏界面的更新频率），脚本无法强制。

## 常见问题

**显示"未配置"** —— `Parameter` 没填或格式不对。必须是 `基地址|Key`，
中间用竖线分隔。

**一直显示"离线"** —— 检查：
1. 手机能不能访问 `https://canisa1ph.duckdns.org:8443/healthz`（用 Safari 试）
2. Key 是否被吊销（控制台 → 设置 → API Key，看 `last_used_at` 有没有更新）
3. 服务器上 `systemctl is-active schedulekit`

**任务顺序不对** —— 小组件完全按服务端返回的顺序渲染，
而排序是服务端的职责（有序表按截止时间升序、无序表按优先级）。
如果你觉得排序不对，那是服务端的问题，不是小组件的问题。

**想只显示某一门课的任务** —— 当前接口不支持按课程过滤。
真需要的话，可以在快捷指令里拉全量再自己筛。

**锁屏组件显示空白 / 不更新** —— 依次检查：
1. 系统设置 → 专注模式/锁屏，是否允许该组件显示（锁屏组件默认可能被隐藏）
2. `Parameter` 是否也填了（锁屏与主屏是**两个独立的组件实例**，
   各自要填一次参数）
3. iOS 版本是否 ≥ 16（锁屏小组件是 iOS 16 才有的）
4. 锁屏组件的刷新由系统调度，不会像主屏那样每 15 分钟必刷

**锁屏矩形里文字被截断** —— 属预期：锁屏空间固定（约两行），
标题会自动缩小到 80% 再截断。想看到完整标题请用主屏的中/大尺寸。

## 改这个脚本时注意什么

脚本里有两个**很容易犯、而且看不出**的错误，都已经被测试钉住：

1. **子元素加错父节点**。`taskRow()` 会先 `host.addStack()` 建"一行"，
   之后所有零件必须加到那个 stack 上。加到 `host`（父容器）上不会报错，
   但"行"会被摊平成垂直流 —— 表现是标题、圆点、时间各占一行地错位。
2. **没声明主轴方向**。顶层不调 `w.layoutVertically()` 时，
   `addSpacer()` 不会把内容推到底部，整个组件会居中/错位。

这两条在代码里都读不出来（iOS 只在组件真正上屏后才渲染），所以
`tests/test_widget_structure.py` 用假的 Scriptable API **真的执行**这个脚本，
把元素树 dump 出来做结构断言（含"标题必须落在横向行里"）。
改完脚本请跑：

```bash
uv run pytest -q -p no:cacheprovider tests/test_widget_structure.py
```

## 与快捷指令的分工

| | 快捷指令 | 小组件 |
|---|---|---|
| 方向 | **写**（录入） | **读**（展示） |
| 权限 | `scope = write` | `scope = read` |
| 交互 | 主动触发（拍照） | 被动刷新（主屏） |
| 文档 | [`shortcuts.md`](shortcuts.md) | 本文件 |

两者用**两个不同的 Key**：写权限的 Key 只存在快捷指令里（用得不频繁、也更容易
意识到它的价值），只读 Key 存在小组件里（暴露面更大）。这样即使小组件的 Key 泄漏，
损失也限于"别人能看到你的待办"，而不是"能改"。
