# Apple 快捷指令：拍照录入

目标：**拍一张照（可加一句文字备注）→ 任务进草稿箱 → 打开确认页核对入库。**

整条链路的成本应该低到"路上看到作业群消息就能拍一下"。

---

## 端到端形状

```
拍照 → 转成 JPEG → POST /api/ingest (image + 可选 text)
     → 返回 { draft, confirm_url }
     → 打开 confirm_url（Safari，已登录的会话直接可用）
     → 在确认页改完点确认 → 入库
```

---

## 逐步搭建

### 1. 先把 API Key 准备好

网页控制台 → 设置 → API Key → 新建 → 名字填 `iphone-shortcut` → **不要**勾只读
（录入要写权限）。

创建后**明文只显示一次**，复制它。建议存到「密码」App 里备用。

### 2. 新建快捷指令

打开「快捷指令」→ 右上角 `+` → 命名 `记一件任务`。

#### 动作一：拍照

搜索 **拍照**（Take Photo）→ 添加。把它的「精确」关掉（不需要定位）。

> 可选：想从相册选就换成 **选择照片**。
> 想两者都要，可以用「从菜单中选取」分支。

#### 动作二：转成 JPEG（**必须，最容易漏**）

搜索 **转换图像**（Convert Image）→ 添加 → 设置：

- 图像：`照片`
- 格式：**JPEG**
- 质量：`0.7` 左右够用（原图 3–5MB，压完 300–800KB，上传快很多）

**为什么必须转**：iPhone 默认拍 HEIC，而服务端只收位图（JPEG/PNG/WebP/GIF）。
服务端会用 Pillow 真解一次并**明确拒绝** HEIC，而不是假装成功——
但如果这里不转，你每次都会得到一个 422，看起来像"服务坏了"。

#### 动作三：问一句文字备注（可选）

搜索 **要求输入**（Ask for Input）→ 添加 → 设置：

- 输入类型：`文本`
- 提示：`备注（可留空）`

> 不喜欢每次都被问？把这个动作删掉，或者用「如果」包起来只在需要时问。

#### 动作四：上传

搜索 **获取 URL 内容**（Get Contents of URL）→ 添加 → 展开设置：

| 字段 | 值 |
|---|---|
| URL | `https://canisa1ph.duckdns.org:8443/api/ingest` |
| 方法 | `POST` |
| 请求体 | `表单`（Form） |
| 头部 | 新增一条：键 `Authorization`，值 `Bearer sk_你的Key` |

然后在「请求体 → 表单」里加两个字段：

| 键 | 类型 | 值 |
|---|---|---|
| `image` | 文件 | `已转换的图像`（即动作二的输出） |
| `text` | 文本 | `提供的输入`（即动作三的输出） |

> **字段名必须完全一致**：`image` 与 `text`。服务端不认别的名字。
> 传字文字时 `text` 可以留空，但**字段本身建议保留**（服务端允许空值）。

#### 动作五：打开确认页

从上传结果里取出 `confirm_url`：

1. 搜索 **获取词典值**（Get Dictionary Value）→ 添加
   - 获取：`URL 内容`（上一步的响应）
   - 键：`confirm_url`
2. 搜索 **打开 URL**（Open URLs）→ 添加 → URL 填上一步的结果

> 用 `confirm_url` 而不是自己拼地址：服务端返回的是配置里的 `public_url` +
> `/#/drafts/{id}`，换域名/端口时只改配置一处。

### 3. 加到主屏或负一屏

- 长按快捷指令 → 详细信息 → 添加到主屏幕（可以选个图标）
- 或者放到「操作按钮」（iPhone 15 Pro 及以上）：设置 → 操作按钮 → 快捷指令

## 响应长什么样

```jsonc
{
  "draft": {
    "id": 12,
    "status": "pending",
    "item_count": 2,
    "llm_path": "tool_call",
    "fallback_note": null,
    "items": [
      { "title": "第三章习题", "category": "homework",
        "due_at": "2026-10-10T15:59:00+00:00", "priority": null, "notes": "只做奇数题" },
      { "title": "背单词", "category": "practice",
        "due_at": null, "priority": 3, "notes": "" }
    ],
    "overrides": [],
    "seconds_left": 172800
  },
  "confirm_url": "https://canisa1ph.duckdns.org:8443/#/drafts/12",
  "message": "识别到 2 条事项，请在确认页核对后入库。"
}
```

**此时任务表里什么都没有。** 只有你在确认页点确认才入库。

## 四个必踩的坑

### 坑 1：HEIC 没转 JPEG

**症状**：每次都是 422，`detail` 里写着「无法识别为图片。可能原因：…格式是 HEIC」。

**原因**：iPhone 默认以 HEIC 拍摄或存储。服务端只收位图。

**修法**：动作二「转换图像 → JPEG」。这一步不能省。

> 服务端刻意**不**静默接受 HEIC：那需要额外的解码库、且会掩盖"你漏了转换"这件事。
> 明确拒绝比"大多数时候能用但偶尔失败"好。

### 坑 2：`Authorization` 头没生效

**症状**：401「未登录或会话已失效」。

**原因**：三种常见情况——
1. 写成了 `authorization` 或 `Auth`（HTTP 头名不区分大小写，但快捷指令的**键**
   要和你在服务端看到的写法一致才不会自己看错）
2. 漏了 `Bearer ` 前缀（注意后面**有一个空格**）
3. Key 前面/后面带了空格（从网页复制时容易带上）

**修法**：值填成 `Bearer sk_xxxx`，粘完检查首尾没有空格。
自查：

```bash
curl -H "Authorization: Bearer sk_你的Key" \
  https://canisa1ph.duckdns.org:8443/api/auth/whoami
# 应当返回 {"kind":"apikey","scope":"write",...}
```

### 坑 3：把图片传成了文本

**症状**：201 但 `item_count` 是 0，或 `detail` 说「请提供图片或文字中的至少一项」。

**原因**：表单里 `image` 字段选成了「文本」类型，快捷指令就把图片的**文件名**
当字符串传了。

**修法**：`image` 字段的类型必须是「文件」。

### 坑 4：确认页打不开（或反复要求登录）

**症状**：打开 `confirm_url` 后跳到登录页。

**原因**：Safari 里没有有效的会话 Cookie（没登录过，或改过密码）。

**修法**：先在 Safari 里登录一次网页控制台。会话默认 30 天，
且会滑动续期（老于一天的会话在下次请求时换新票）。

> 这是刻意的：原图与草稿内容**不开放匿名访问**（图里可能有群名、学号），
> 所以确认页需要会话。如果你希望"扫一眼就能改"，那需要另一套设计
> （例如一次性 token 链接），目前没做。

## 变体：只要文字，不要图

把动作一换成「要求输入」文本，然后：

- 请求体表单里**只**留 `text` 字段
- 删掉 `image` 字段与「转换图像」动作

适合"老师口头说了一句作业"这种场景。

## 变体：一次记多条

在「要求输入」里允许换行，一次写多行：

```
下周一交第三章习题
周五之前复习复变
有空背单词
```

服务端会把它当一段文字交给模型，模型按行拆成多条事项。
（本项目自带的 `mock` provider 也会按换行拆，方便你在没有 API Key 时先试链路。）

## 排障

**看服务端到底收到了什么**：每次响应都带 `X-Trace-Id` 头。
在快捷指令里加一个「显示结果」动作把响应打出来，或者在服务器上：

```bash
journalctl -u schedulekit | grep 'ingest.received'
journalctl -u schedulekit | grep 't=那个trace_id'
```

**识别结果不对**：先看上下文对不对，而不是先怀疑模型——

```bash
curl -H "Authorization: Bearer sk_你的Key" \
  https://canisa1ph.duckdns.org:8443/api/ingest/context
```

它会返回**本次识别会注入的完整上下文**（时间、第几周、正在上什么课、注入了哪些记忆）。
"识别错了"最常见的原因是这个上下文里的日期/周次不对，而不是模型不行。
